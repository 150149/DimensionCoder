# C/C++ 编写规范（参考 c-coding-standards）

## 代码结构与命名

- 命名：变量/函数 `camelCase`，常量/宏全大写下划线，结构体 `PascalCase` 或 `snake_case`（与现有风格一致）；文件夹名小写
- 名称中严禁混合拼音和英文，严禁使用中文；命名必须清晰、有业务意义
- 不使用 class（用 struct + 自由函数）；不使用自定义命名空间（全局作用域）；避免 typedef；接收强转类型用 auto
- 使用 CMake 作为构建工具；不能使用 try-catch 捕获异常（编译器不支持异常处理机制）；能不用结构体尽量不用结构体；不允许在头部声明函数（应调整函数顺序）
- JNI 场景：jvmTiEnv 必须在 jniEnv 前面

## 头文件

- 新头文件统一 `#pragma once`（不用 `#ifndef` 守卫）
- 系统/标准库头文件用 `<>`，项目头文件用 `""`；必要的项目 Utils.h 引入按相对路径调整

## 注释

- 不写新注释，代码应当自解释（与周围代码注释密度一致）

## 代码质量

- `if` 必须加大括号（即使只有一行）
- 禁止 `if(!xxx) {b} else {a}`，必须 `if(xxx) {a} else {b}` 正向逻辑优先
- 单个函数圈复杂度严禁超过 15；单函数总行数 ≤40；不要出现小于 5 行的函数
- 单个循环中 `break` 和 `continue` 合计最多使用一个
- 重复代码行数不能超过 5 行（超出提取独立函数）；魔法字符串超过 3 个必须定义为常量
- 函数与函数之间必须留有空行
- 返回值从未被使用的函数，返回类型应改为 `void`
- 单一职责；复杂逻辑拆分；善用设计模式；Wrapper 封装相近但不相同的逻辑
- 函数式风格：不允许修改传入参数（传参加 `const`）
- 不能为效率牺牲可读性；避免过时 API；写完代码必须重新读取文件确认无语法错误
- 禁止 static 修饰函数（函数声明不添加 `static inline`）
- CPP 文件代码顺序：`#include` → 宏 → 全局变量 → 结构体 → 函数（类型间空行）

## 敏感数据 & 密钥安全

- 密钥解密后立即使用，用完立刻清零（`SecureZeroMemory` 或 volatile 写零）
- 禁止明文密钥存入全局/静态变量；密钥生命周期最小化（栈上缓冲区，离开作用域前清零）
- 硬编码敏感字符串必须用 `EncryptedString` / `SECURE_STRING()` 宏

## JNI 约定（Android 反作弊场景）

- JNI 函数 C-style 接口：`(*env)->Method(env, ...)`；导出函数标记 `JNICALL`
- JNI 类引用通过 `NewGlobalRef` 缓存 + `std::atomic_flag` 线程安全初始化
- 安全关键路径用 `VM_ENABLE`/`OBF_ENCRYPT` 标记；性能敏感路径用 `OBF_TIME_CRITICAL`
