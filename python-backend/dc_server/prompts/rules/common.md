# 通用代码编写规范（所有语言，必查）

## 命名

- 命名必须清晰、准确表达变量/函数/类的用途，具有业务意义
- 严禁名称中混合使用拼音和英文，严禁使用拼音命名
- 命名风格与所在文件/模块的既有风格保持一致（不强改存量代码风格）
- 布尔变量用 `is_/has_/should_` 等前缀表达语义；集合用复数；计数器用 `count/index`

## 函数与结构

- 单个函数只做一件事（单一职责），复杂逻辑必须拆分成多个简单函数
- 单个函数总行数尽量不超过 40 行（超长函数必须拆分）
- 圈复杂度尽量不超过 15（嵌套过深 `if/else`、多重循环是重点）
- 同一段重复代码超过 5 行必须提取为独立函数（DRY）
- 返回值从未被使用的函数，返回类型应改为 `void/None`（或明确消费）
- 函数与函数之间必须留有空行

## 条件与流程

- `if` 必须加大括号/缩进块，即使只有一行
- 正向逻辑优先：禁止 `if(!xxx) {b} else {a}` 的负向优先写法，应写成 `if(xxx) {a} else {b}`
- 单个循环中 `break` 和 `continue` 合计最多使用一个（多个说明循环逻辑混杂）
- 深层嵌套用提前返回（guard clause）平铺

## 常量与魔法值

- 魔法字符串/数字超过 3 处必须定义为常量（常量名全部大写，如 `MAX_RETRY`）
- 硬编码值应为常量或配置项，不得散落在业务代码中

## 其他

- 写完代码后必须重新读取文件确认修改成功且无语法错误（自查，不留低级错误给审查）
- 不为效率牺牲可读性；可以牺牲部分效率提升可读性
- 避免使用过时 API，依赖项保持合理版本
- 注释：代码应当自解释；写注释时密度与周围代码一致（存量代码注释多则多写、注释少则少写，不强制统一）
